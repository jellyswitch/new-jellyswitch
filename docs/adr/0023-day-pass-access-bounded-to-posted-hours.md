# Day-pass access and self-serve bookings are bounded to posted hours (time-of-day, not staffed days)

Nash incident, 2026-08-07 (Cowork Tahoe): an unapproved 1:19 AM signup bought a $100 Day Office pass at 1:34 AM and the Lobby Door opened at 1:38 AM — hours are 5 AM–8 PM. The door gate's day-pass clause (`day_passes.where(day: today)`) checked the pass's DATE but never the clock, so a pass valid "today" opened building doors 24/7; the same held for bundle holders. Booking had the same hole from the other side: `reserve_now` starts a booking RIGHT NOW at any hour, and `reservations#create` never validated hours server-side, so any reservation minted an ADR 0013 ±window door grant at night. We decided: **day-pass and bundle building access, and member self-serve bookings (create/move/extend), are bounded to the location's posted working hours — the time-of-day window only (`Location#within_posted_hours?`), NOT the `open_<day>` staffed-days flags.** A prod audit before shipping found ~20 weekend-daytime day-pass entries in 30 days at Cowork Tahoe alone (all live locations flag sat/sun closed) — established, accepted, paying behavior a day-flag gate would have broken; the flags describe when staff are present, not when access is allowed. A day-pass TYPE flagged `always_allow_building_access` keeps 24/7 access — the same escape hatch membership plans get via the `all_hours` tier (ADR-adjacent: plan `building_access_level`). Membership tiers, leases, staff, and the reservation ±window (ADR 0013) are unchanged: a booking is still its own access grant, which stays sound because bookings themselves are now hours-bounded for hour-bounded users. Enforcement is one organizer step, `EnforcePostedHours`, first in both create organizers, opt-in via `enforce_posted_hours` (mirrors ADR 0019's `enforce_coverage`) so admin/on-behalf flows keep booking anything; the web Keys list predicate (`has_building_access?`) got the same bound as the unlock gate so list and tap can't diverge (the PR #668 invariant).

## Considered Options

- **Bound to `open_at?` (hours + open-day flags)** — rejected: would have locked out weekend daytime day-pass holders at every live location (flags say closed sat/sun everywhere); the flags encode staffed days, not access policy.
- **Gate day-pass purchase times instead of access times** — rejected: buying a pass at night for tomorrow morning is legitimate; access, not purchase, is what the hours bound protects.
- **Kisi-side schedules only** — rejected as the primary control: the app is the source of truth for who may enter and shows the Keys UI; hardware schedules remain a worthwhile belt-and-suspenders an operator can add.
- **Bounding via the plans' `building_access_level` machinery** — rejected: day passes and bundles are separate products with an existing per-type 24/7 boolean; reusing it keeps one knob per product instead of a second tier system.
